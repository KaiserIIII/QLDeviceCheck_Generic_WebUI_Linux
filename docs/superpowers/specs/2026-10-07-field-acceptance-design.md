## 产品定位

面向设备厂商、工控系统集成商与交付工程师的 Linux 本地现场验收工作台。把设备配置转为验收清单，在执行过程中记录证据，交付后可以复测和比较。离线演示让面试、售前和培训无需连接现场设备。

目标差异化组合：配置驱动的应检设备覆盖 + 串口/网络/PCI 共用验收视图 + 通信路径与业务功能分级 + 故障证据 + 同配置复测对比 + 本机部署。这是产品方向判断，不宣称市场独占、已获客户或已经改善效率。

## 路线选择

| 路线 | 内容 | 取舍 |
|---|---|---|
| A：现场验收闭环（推荐） | 异步任务、应检清单、证据、历史记录、基线对比、演示、工程验证 | 在现有协议能力上形成可演示和可交付的业务流程 |
| B：界面与报告增强 | 美化界面，增加导出、文档和截图 | 较快，不能解决漏检和结果追溯问题 |
| C：集中设备管理平台 | 多站点、账号、资产、远程代理、工单、调度 | 运维和安全范围明显扩大，超出本轮验收工具定位 |

采用 A。第一版针对单个工位，不做多站点云管理。

## 本轮功能

### 1. 应检设备与验收判定

- 验收以配置中的设备清单为范围；展示应检、完成、通过、失败、待确认及未执行数量。
- 未发现或未响应设备也生成记录，不因扫描过滤而消失。
- 结果明确区分 PASS、FAIL、REVIEW、NOT_RUN；存在失败、待确认或未执行时，整体不得显示全部通过。
- 继电器通过透明 IO 路径响应，仅证明通信路径；PCI 被动检查只证明实际采集的被动状态，不宣称业务功能或电气动作正常。
- 保留现有全量扫描、单接口扫描、单设备复测能力和配置格式。

### 2. 异步任务与追溯

- 创建任务填写工位/设备编号、批次、操作者和备注，均有长度约束；支持验收和指定设备复测。
- 后台执行，浏览器轮询状态。一个工位同一时间只允许一个硬件任务，冲突返回 409。
- 任务状态 queued、running、cancelling、completed、cancelled、failed、interrupted。取消在设备边界生效；不伪装成即时终止串口或网络操作。
- SQLite 保存任务、配置快照与 SHA-256、设备结果、原始证据、事件和实际耗时。服务重启时未完成任务标为 interrupted，不自动连接硬件重跑。
- 任务创建时固定配置快照；运行中配置变化不改变正在执行的任务。
- 每个结果有接口、协议、通信范围、请求/响应、失败分类及基于规则的排查建议。不能把规则建议表述为已确定根因。
- 新任务数据库与已有 report 目录分离，不删除历史文件。

### 3. 历史、复测和导出

- 历史任务支持状态和文本筛选、分页、查看详情与按失败设备创建复测。
- 比较两次任务：新增、移除、恢复、退化、仍失败、其他变化、未变化。
- 模式和配置摘要一致时才能显示可比结论；不一致时明确提示，设备差异仅供查看。
- HTML、JSON、CSV 导出包含任务元数据、判定、证据和配置摘要；CSV 防止公式注入，HTML 转义不可信内容。
- 演示报告固定标记 SIMULATED，不混入真实设备通过率；统计仅来自已保存任务。

### 4. 硬件独立演示

- 独立 --demo 启动入口，使用内置合成设备清单与确定性 Fake 适配器，不初始化现场扫描或真实连接。
- 场景覆盖正常、响应超时、CRC 错误与设备缺失；可以演示故障验收、失败复测、正常恢复及前后对比。
- UI 始终显示演示模式和模拟证据。演示场景不等于真实硬件兼容性验证。
- 真实模式继续默认绑定 127.0.0.1。公开到局域网需要配置访问令牌，并在 UI 输入会话凭证；凭证不进入 URL、报告和日志。

### 5. 架构和界面

```text
浏览器：工位总览 / 新建验收 / 设备清单 / 任务详情与证据 / 历史对比
  -> HTTP 输入校验与访问边界
  -> InspectionService（验收范围、任务状态、取消、复测）
  -> DetectorAdapter / DemoAdapter（统一结果契约）
  -> 已有 GenericDetector + protocol_engine

InspectionService -> SQLiteStore（任务、事件、配置快照）
已保存任务 -> ComparisonService / ReportExporter
```

- 新业务模块按任务、持久化、适配、判定、比较和导出拆分；HTTP 不直接操作串口和 socket。
- 复用现有配置与底层协议，不为了展示架构更换成微服务。
- 单页前端拆分本地 CSS/JS，脱离 CDN，保留窄屏操作；包含进度、状态标签、故障证据侧栏与恢复对比。
- HTTP 限制请求大小、验证枚举与资源 ID，错误不返回 traceback；检查非同源浏览器请求。
- 自定义指令仍需对设备语义进行人工审查；单凭 operation=read 标签无法保证物理动作安全。

## 接口契约

| 接口 | 行为 |
|---|---|
| GET /api/health | 版本、模式、任务状态和持久化就绪信息 |
| GET /api/catalog | 当前模式下设备清单与配置摘要 |
| POST /api/config/validate | 校验上传 JSON，不写入现场配置 |
| POST /api/jobs | 创建验收/复测任务，202 返回任务 ID |
| GET /api/jobs | 分页和筛选任务 |
| GET /api/jobs/{id} | 状态、事件、结果和证据 |
| POST /api/jobs/{id}/cancel | 请求取消，最终状态在设备边界更新 |
| POST /api/jobs/{id}/retest | 从已保存失败项创建复测，保持原配置快照 |
| GET /api/compare?baseline=...&current=... | 可比性和设备差异 |
| GET /api/jobs/{id}/export?format=html/json/csv | 任务报告 |
| GET /api/insights | 按真实/演示模式分开的实际运行统计 |

原有 /api/scan、/api/scan-interface、/api/run、/api/test-device 的兼容入口保留，统一互斥并明确旧格式与新任务记录的边界；演示模式下不得通过兼容入口访问真实硬件。

1. 保留既有离线自检；新增 pytest 覆盖任务状态、持久化恢复、取消、复测、预期设备缺失、比较与导出。
2. Fake 和回环协议测试覆盖超时、断线、分段响应、错误 CRC、事务号/功能码/长度不匹配和写操作禁止。
3. 从真实 HTTP 入口验证所有新增接口、错误输入、访问边界与互斥；不调用现场设备。
4. 浏览器跑通“故障演示验收 -> 查看证据 -> 导出 -> 恢复复测 -> 比较”，检查桌面与窄屏并保存截图。
5. 报告实际覆盖率与未覆盖风险。Windows 无法证明银河麒麟、Linux 串口权限、驱动和真实设备兼容性；这些明确列为现场验收项目。
6. 依赖不递归安装 Skill；必要依赖记录来源、许可证、审核 commit 和安装时间，版本固定。CI Action 固定审核 commit。
7. 中英文 README、架构说明、部署和演示手册、API、变更记录与实际测试结果随代码交付。沿用远程已有 MIT 许可证。
8. 验证后推送 codex/field-acceptance-workbench 分支，创建附测试结果的 GitHub PR，更新仓库供评审；不把未验证功能描述为已生产就绪。
